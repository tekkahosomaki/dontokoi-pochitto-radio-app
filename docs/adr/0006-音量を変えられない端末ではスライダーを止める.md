# ADR-006: 音量を変えられない端末では、スライダーを止めて本体のボタンを案内する

- **ステータス**: 採用
- **背景**: iPhone で公開ページを開くと、音量スライダーを動かしても音の大きさが変わらなかった。iPhone・iPad では、Safari だけでなく Chrome や Edge も Apple の決まりで Safari と同じ仕組み(WebKit)で動き、どのブラウザでもページから音量(`audio.volume`)を変えられない。設定しても無視され、値は 1 のままになる。Android やパソコンのブラウザでは変えられる。[ADR-004](0004-audioタグで再生する.md) でも、この制限は書いていた。
- **決定**: ページを開いたときに、試しの `<audio>` の音量を 0.5 にしてみて、値が 0.5 にならなければ「音量を変えられない端末」と判断する。その場合は音量スライダーを押せない状態(薄い表示)にし、数値の代わりに「音量は本体のボタンで調整」と表示する。
- **検討した代替案**: ブラウザの名前(User-Agent)で iPhone・iPad を見分ける案(iPad はパソコンの Safari と同じ名前を名乗ることがあり、見分け間違いが起きるため不採用。実際に変わるかを試すほうが確実)。Web Audio API の音量調整(GainNode)を通して iPhone でも音量を変えられるようにする案(放送局側の許可(CORS)がない Rinse FM などは音が出なくなるうえ、iPhone では画面を消すと再生が止まりやすくなるため不採用。[ADR-004](0004-audioタグで再生する.md) の方針も変わる)。何もしない案(スライダーが動くのに音が変わらず、壊れているように見えるため不採用)。
- **結果・影響**: iPhone・iPad では、スライダーが効かない理由が画面でわかる。それ以外の端末では今までどおりスライダーで音量を変えられる。将来 iPhone で音量を変えられるようになれば、判定が自動で「変えられる」に変わり、スライダーが使えるようになる。動作確認は、パソコンのブラウザで音量が変わらないよう細工したテスト用のコピーで行った(実機の iPhone での確認は横尾さんに依頼)。
